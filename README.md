# ابر رباتساز — Azadi BotMaker

پلتفرم ساخت هر ربات و مینی‌اپ تلگرامی بدون کدنویسی: هوش مصنوعی + نقشه‌های آماده (Blueprint) + استودیوی گرافیکی + مینی‌اپ‌ساز بلوکی + مرکز بازی + رشد واقعی + عامل هوشمند. **نسخه‌ی BUILD 3.3.0** (پرامپت ابرارتقای ۳).

## نصب و اجرا

```bash
pip install -r requirements.txt        # Flask gunicorn pymongo requests cryptography mongomock telethon Pillow
python -m py_compile *.py              # بررسی سلامت
gunicorn app:app --workers 2 --threads 4   # یا: python app.py
```

## Environmentها

| کلید | الزامی | پیش‌فرض | توضیح |
|---|---|---|---|
| `MOTHER_TOKEN` | ✅ | — | توکن ربات مادر |
| `BASE_URL` | ✅ | — | مثل `https://app.onrender.com` |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` | ✅ | — | سازگار با OpenAI؛ `AI_CHAT_MODEL` اختیاری (مدل سبک گفتگو) |
| `MONGO_URI` | — | حافظه‌ی موقت | حتماً در پروداکشن ست شود |
| `SECRET_KEY` | — | MOTHER_TOKEN | کلید رمزنگاری توکن‌ها و امضاها |
| `ADMIN_IDS` / `ADMIN_WEB_KEY` | — | خاموش | ورود ادمین از مرورگر با `/?key=…` |
| `MOTHER_USERNAME` | — | از getMe | برای لینک‌های دعوت |
| `BILLING` | — | usage | `fixed` = هزینه‌های ثابت |
| `MAX_NODES` / `MAX_BOTS` / `PACKS` / `REF_*` و… | — | بخشید | سقف‌ها و اقتصاد توکن |

هیچ Environment جدیدی برای قابلیت‌های نسخه ۳ لازم نیست؛ همه‌چیز پیش‌فرض روشن است.

## ساختار فایل‌ها (وابستگی: core ← ai ← engine ← growth/games ← webapp ← mother ← app)

- `core.py` — تنظیمات، دیتابیس، کیف توکن، پلن‌ها، ایندکس‌ها، `limits_of` پلن‌محور
- `caps.py` — **رجیستری قابلیت‌ها** (منبع واحد برچسب‌های فارسی رویداد/کار/دکمه/بلوک/بازی) + `BUILD`
- `ai.py` — پرامپت AI (آگاه از CAPS)، `sanitize` کانفیگ ربات، BM25 دانش، قالب‌های ربات
- `engine.py` — موتور اجرای ربات‌ها (اکشن‌ها، تیکت، یادآور، مدیریت گروه، پرداخت، دانش عامل)
- `games.py` — مرکز بازی سمت سرور (۹ بازی، سکه، رتبه دوره‌ای، دوئل، فروشگاه؛ مسیرهای `/rt/<id>/game/*`)
- `growth.py` — رشد فقط با ورود واقعی (لینک دعوت تلگرام، `chat_member`، کسر در خروج، ضدتقلب)
- `webapp.py` — مینی‌اپ‌ساز (`sanitize_app` ۸۱ بلوک، رانتایم `/a` و `/rt`، ۱۳ قالب، CSP)
- `blueprints.py` / `architect.py` — نقشه‌های آماده B1–B6 و معمار (تشخیص ← ۳ سؤال ← ساخت ربات+مینی‌اپ ← خودآزمایی ← پچ با کارت فارسی)
- `app.py` — مسیرهای HTTP پلتفرم (ربات‌ها، لیست‌ها، نسخه‌ها، دکتر ربات، دانش عامل)
- `mother.py` — ربات مادر، یوزربات، پرداخت کارت‌به‌کارت
- `static/` — `app.js` (پوسته) ← `studio.js` ← `studio2.js` (وقتی‌آنگاه، شبیه‌ساز، مشکل‌ها، دکتر، لیست‌ها، رشد، عامل) ← `builder.js` ← `builder2.js` (گالری ۸۱ بلوک، تم‌ها، منو، کامپوننت) و `mapp.js` (رانتایم مینی‌اپ)

نکته: بعد از هر تغییر در فایل‌های static، مقدار `BUILD` را در `caps.py` بالا ببرید تا کش مرورگر و تلگرام تازه شود (به‌صورت خودکار `?v=` به همه‌ی assetها می‌خورد).

## امنیت (اصل ثابت)

هیچ کد کاربر اجرا نمی‌شود — همه‌چیز JSON اعتبارسنجی‌شده با `sanitize`/`sanitize_app` و موتور ثابت است. شانس و منطق بازی سمت سرور است. توکن ربات‌ها با Fernet رمز شده. احراز هویت مینی‌اپ هر ربات با initData امضاشده با توکنِ همان ربات انجام می‌شود. CSP رانتایم شامل media-src و frame-ancestors تلگرام است.


## پیکربندی مدل‌های جایگزین هوش مصنوعی

برای اینکه با رد شدن درخواست یا خطای یک مدل، ساخت روی همان مدل گیر نکند، متغیر محیطی `AI_MODELS` را در Render اضافه کنید. مدل‌ها را با کاما و به ترتیب اولویت بنویسید؛ همه باید از همان `AI_BASE_URL` و `AI_API_KEY` فعلی پشتیبانی شوند (API سازگار با OpenAI Chat Completions). نمونه:

```text
AI_MODEL=provider/model-primary
AI_MODELS=provider/model-primary,provider/model-secondary,provider/model-third
```

`AI_MODEL` باید ترجیحاً یک شناسهٔ مدل باشد و فهرست جایگزین‌ها را در `AI_MODELS` قرار دهید. برای سازگاری، کد جدید فهرست‌های جداشده با کاما، سمی‌کالن یا خط جدید را هم در `AI_MODEL` می‌شکند؛ بنابراین اگر قبلاً کل فهرست را اشتباهاً داخل `AI_MODEL` گذاشته‌اید، دیگر آن رشتهٔ کامل را به‌عنوان یک مدل ارسال نمی‌کند. به‌طور پیش‌فرض در هر عملیات حداکثر ۳ مدل یکتا امتحان می‌شوند (`AI_MAX_MODEL_TRIES` را می‌توان تا ۵ تنظیم کرد). شناسه‌های embedding مانند `gemini-embedding-001` خودکار از فهرست ساخت متنی کنار گذاشته می‌شوند، چون برای Chat Completions مناسب نیستند. خطای نحوی JSON نیز باعث می‌شود مدلِ خروجی نامعتبر در تلاش بعدی کنار گذاشته شود؛ JSON فقط با ترمیم نحوی محدود اصلاح می‌شود و اگر ساختار هنوز نامعتبر باشد، خروجی تحویل داده نمی‌شود.

برای ارائه‌دهندگانی که سقف طول هر پیام دارند، پس از خطای صریح طول پیام، متن دستورالعمل حذف یا کوتاه نمی‌شود؛ پیام‌های بلند به بخش‌های کوچک‌تر با نقش یکسان تقسیم می‌شوند. سقف هر بخش با `AI_MAX_SINGLE_MESSAGE_CHARS` (پیش‌فرض ۳۵۰۰ نویسه؛ بازهٔ ۱۰۰۰ تا ۷۰۰۰) قابل تنظیم است. نام‌های داخلیِ فقط‌خواندنی که اشتباهاً در موقعیت ذخیره‌سازی استفاده شوند، پیش از اعتبارسنجی به نام امن معادل تبدیل می‌شوند (برای نمونه `name` به `customer_name`) تا مقدار فرم بی‌صدا حذف نشود. برای درخواست‌هایی که فقط نام یک ربات مرجع دارند، ساخت یک نمونهٔ شروع ممکن است اما بازتولید دقیق بدون شرح قابلیت‌ها/تصویرها تضمین نمی‌شود.

برای کنترل زمان‌ها، `AI_GENERATION_TIMEOUT` زمان سقف هر مدل هنگام تولید کانفیگ (پیش‌فرض ۸۰ ثانیه)، `AI_MODEL_TIMEOUT` سقف هر مدل برای ممیزی/فراخوانی‌های معمول (پیش‌فرض ۳۵ ثانیه) و `AI_BUILD_DEADLINE` بودجهٔ کل هر ساخت (پیش‌فرض ۳۰۰ ثانیه) هستند. `AI_MAX_MODEL_TRIES` هم تعداد مدل‌هایی را که در هر مرحله امتحان می‌شوند کنترل می‌کند (پیش‌فرض ۵، سقف ۵). اگر مهلت کل تمام شود، کار با شکست روشن متوقف می‌شود؛ خروجی تأییدنشده ذخیره نمی‌شود و هزینه‌ای کسر نمی‌شود. `BOT_BUILD_TIMEOUT` پیش‌فرض ۳۶۰ ثانیه است و می‌تواند برای سازگاری با محیط شما تنظیم شود.

**مهم:** این فهرست فقط شناسهٔ مدل‌ها را در یک ارائه‌دهنده/درگاه مشترک عوض می‌کند. برای مدل‌هایی که API، کلید یا نشانی پایهٔ متفاوت دارند، باید مسیر چندارائه‌دهنده با اعتبارنامه‌های جداگانه پیاده‌سازی شود؛ صرف افزودن نام آن‌ها به `AI_MODELS` کافی نیست.


## دریافت عکس در فرم و مدیر عملیاتی با نام کاربری

- نوع سؤال فرم `photo` برای دریافت اجباری عکس و `photo_optional` برای دریافت اختیاری تصویر است. برای گزینهٔ رد کردن، `skip` باید آرایه‌ای هم‌اندازهٔ `fields` باشد؛ برای نمونه: `{"fields":["عنوان","عکس را بفرست"],"types":["text","photo_optional"],"skip":["","عکس ندارم"]}`. گزینهٔ رد کردن یک دکمهٔ Reply Keyboard واقعی است، نه Alert نمایشی. عکس‌های ارسال‌شده پس از تکمیل فرم همراه با خلاصهٔ پاسخ‌ها برای مدیران تنظیم‌شده فرستاده می‌شوند.
- برای افزودن مدیر عملیاتی با نام کاربری از `desk.staff_usernames` استفاده می‌شود؛ `@` در مقدار ذخیره نمی‌شود. مدیر باید یک‌بار همان ربات ساخته‌شده را باز کند و `/start` بزند تا تلگرام شناسهٔ عددی چت او را در اختیار ربات قرار دهد. تا پیش از این کار، ارسال پیام خصوصی خودکار به صرف دانستن username از طریق Telegram Bot API ممکن نیست.
- این تنظیم مدیر عملیاتی، مالکیت BotFather یا مالک رکورد پلتفرم را منتقل نمی‌کند. مالک اصلی همچنان اختیار مالک را دارد. اگر درخواست صریحاً خواست مدیران عملیاتی قبلی عوض شوند، فهرست مدیران افزوده‌شده با گیرنده‌های نام‌برده‌شده جایگزین می‌شود.
- ربات‌ساز به‌صورت قطعی تلاش می‌کند سؤال عکس و مسیر تأیید نهایی را به ساختار واقعی متصل کند. اگر مقصد فرم مبهم باشد یا سقف امن ظرفیت باعث شود اصلاح قابل‌اعتماد نباشد، نقص باید در گزارش بازبینی بماند؛ نباید صرف وجود عنوان یا دکمه به‌عنوان قابلیت اجراشده گزارش شود.
